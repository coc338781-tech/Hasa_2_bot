# HASA Server Agent

The agent is telemetry-only. It reports host capacity to the central API and has no remote shell, process control, customer-file access or WhatsApp session access. On Linux it reports `MemAvailable` from `/proc/meminfo`, matching the `available` column shown by `free -h`; the owner console uses that live value for RAM admission decisions.

## Requirements

- Linux with systemd
- Node.js 22 or newer
- A reachable HASA BOT NETWORK API over HTTPS
- A one-time server enrollment ticket issued from the owner console

## Install

From the repository checkout:

```sh
cd network/agent
sudo bash install-systemd.sh
sudo nano /etc/hasa-agent/agent.env
```

Set `HASA_AGENT_API_URL` to the HTTPS origin and `HASA_AGENT_ENROLLMENT_TICKET` to the one-time ticket generated by the owner console. Keep the environment file at its installed root-owned, group-readable mode (`0640`).

Start the service:

```sh
sudo systemctl enable --now hasa-agent
sudo journalctl -u hasa-agent -f
```

After the log confirms successful enrollment, remove the `HASA_AGENT_ENROLLMENT_TICKET` line from `/etc/hasa-agent/agent.env` and restart the service. The per-server token remains in `/var/lib/hasa-agent/credentials.json`, owned by the service account and mode `0600`. Do not copy this file to another server.

The agent reports every 60 seconds by default. Configure `HASA_AGENT_INTERVAL_SECONDS` between 15 and 3600 seconds. It requires HTTPS for remote APIs; HTTP is allowed only for localhost development.

## Remove

```sh
sudo systemctl disable --now hasa-agent
sudo rm -f /etc/systemd/system/hasa-agent.service
sudo rm -rf /opt/hasa-agent /etc/hasa-agent /var/lib/hasa-agent
sudo systemctl daemon-reload
```

Revoking the server in the owner console invalidates its agent credential immediately. Removing local files does not delete the server's central audit history.
